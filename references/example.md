# 対照例

以下はすべて、同じ回のポッドキャスト（Next Token 第4回、Muse の部分）の実際の改稿の過程から取ったものだ。元の原稿は録音どおりにまとめた話し手を軸にした版で、完成稿は公開版だ。

> 訳注: 原文は中国語の原稿を例にしている。ここでは日本語に訳して示すので、字数は中国語の原稿の値で、言い回しの細部も訳したものだ。

## 零、まず要点の整理がどういうものかを見る

記事を書く前に作る事実一覧は、話題ごとにまとめ、1行に1項目を書き、括弧の中に章番号を書く。

```
## A. 大ヒットした

1. どのソフトウェアも、そのコネクタストアに入ると株価が1日で最低でも10％上がり、13％上がったものもある。Meta は2兆ドルまで上がった。（06）
2. かつて Alexandr Wang の会社を買収したとき、多くの人がザッカーバーグは頭がおかしい、数百億ドルでこんなものを買ったと罵った。今ではその人物が1日で Meta を2兆ドル上げた。（06）
3. 杨攀: Muse は新しいストアだ。前はアップルに載せていたが、今載せるのはエージェントだ。（06）
4. 日間アクティブユーザーは50万人しかいない。（06）
5. 中国語のネット界隈は Meta の実際の価値をわかっていない。Meta の主な製品を私たちがふだん使わないからだ。Threads の日間アクティブユーザーは実はとっくに Twitter を超えていて、Facebook の広告収入はすさまじい。杨攀はこれをアメリカのテンセントと呼んだ。（06）
6. 杨攀は大手IT企業の社内での一連の講演でこう話した。豆包（Doubao）はもともと数億人向けに作っていた製品だったが、Codex と WorkBuddy がヒットしたので1億人向けの製品に方向を変えた。結局はまた数億人向けに作らなければならないのに、Muse に1か月で覆された。（09）
7. 橘子: Muse はAIバブルを新しい頂点に押し上げた。1億の日間アクティブユーザーがいれば、それは1億台の仮想コンピュータだ。（09）
```

第3、5、6、7項目にも名前を書いている点に注意してほしい。事実一覧の段階では名前を全部残す。この項目が誰の情報で、信用できるかを見て分かるようにするためだ。どの名前を残すかは記事にする段階で決める。

## 一、足場を外す: 元の原稿763字 → 完成稿265字

**元の原稿**

> 歸藏は言う。何よりはっきり示しているのは株価だ。どのソフトウェアも Muse のコネクタストアに加わるだけで、そのソフトウェアの株価は1日で最低でも10％上がり、多いときは1日で13％上がる。Meta 自身は2兆ドルまで上がったのに、Muse の日間アクティブユーザーは50万人しかいない。
>
> かつて Alexandr Wang の会社を買収したとき、多くの人がザッカーバーグは頭がおかしい、数百億ドルでこんなものを買ったと罵った。歸藏は言う。今ではクロックス風のサンダルを履き、迷彩柄の半袖を着たこの人物が、1日で Meta の株価を2兆ドル上げた。
>
> 杨攀のまとめは、Muse は新しいストアだというものだ。前はアップルに載せていたが、今載せるのはエージェントだ。
>
> 中国語のネット界隈は Meta という会社の実際の価値をまったくわかっていない。理由は、Meta の主な製品を私たちがふだんほとんど使わないことだ。でも実は Threads の日間アクティブユーザーは実はとっくに Twitter を超えているし、Facebook の広告収入もすさまじい。実はもっと分かりやすいたとえは、アメリカのテンセントだ。
>
> 杨攀は先週、いくつかの大手IT企業の社内で一連の講演をしたばかりで、彼によると豆包はもともと数億人向けに作っていた製品だったが、Codex と WorkBuddy がヒットしたので1億人向けの製品に方向を変えた。結局はまた数億人向けに作らなければならないのに、Muse がその判断を1か月で覆した。ただ、中秋節のあと、どの大手も残業して似た製品を開発している。
>
> 橘子は言う。Muse はAIバブルをまた新しいピークに押し上げた。彼らが語っている話は、1億の日間アクティブユーザーがいれば、1億台の仮想コンピュータが必要になるというものだ。

**完成稿**

> 何よりはっきり示しているのは株価だ。どのソフトウェアも Muse のコネクタストアに加わるだけで、株価は1日で最低でも10％上がり、多いときは13％上がる。Meta 自身は2兆ドルまで上がったのに、Muse の日間アクティブユーザーは50万人しかいない。
>
> かつて Meta が数百億ドルで Alexandr Wang の会社を買ったとき、外ではさんざん罵られ、何を買ったんだと言われた。今ではザッカーバーグが、クロックス風のサンダルに迷彩柄の半袖で、1日で Meta の株価を2兆ドル上げている。
>
> ひとことでまとめると：Muse は新しいストアだ。前はアップルに載せていたが、今載せるのはエージェントだ。
>
> 中国語のネット界隈は、Meta の実際の価値をずっとわかっていない。いちばん主な製品を私たちがふだんほとんど使わないからだ。実は Threads の日間アクティブユーザーはとっくに Twitter を超えていて、広告収入もすさまじい。Meta はアメリカのテンセントだ。
>
> 杨攀は大手IT企業の社内で一連の講演を終えたばかりだ。彼は言う。豆包はもともと数億人向けに作っていた製品だったが、Codex と WorkBuddy がヒットしたので1億人向けに方向を変えた。結局はまた数億人向けに作らなければならないのに、Muse がその判断を1か月で覆した。中秋節のあと、どの大手も残業して似た製品を開発している。
>
> Muse はAIバブルをまた新しいピークに押し上げた。彼らが語っている話は、1億の日間アクティブユーザーがいれば、1億台の仮想コンピュータが必要になるというものだ。

変えた点は次のとおり。

- 「Xは言う」「Xのまとめは」の6か所のうち5か所を削った。残したのは杨攀の1か所だけだ。その段落は杨攀の独自情報で、本人の名前で示す必要があるからだ。
- 長い文を分けた。「杨攀は先週、いくつかの大手IT企業の社内で一連の講演をしたばかりで、彼によると豆包は……」を2文に分け、紹介の部分を独立した短い文にした。
- 「多くの人がザッカーバーグは頭がおかしい、数百億ドルでこんなものを買ったと罵った」を、「外ではさんざん罵られ、何を買ったんだと言われた」に変えた。元の文は話し手が別の人を評した言葉で、そのまま写すと記事の書き手が人を罵っていることになる。外の反応を描く形に変えれば、口ぶりは残り、責任は書き手に落ちない。あわせて主語の「Meta」を補った。元の「かつて Alexandr Wang の会社を買収したとき」には、誰が買収したかが書かれていなかった。
- 3つの「実は」のうち2つを削った。話し言葉で繰り返される接続語は、文字にするととても目障りだ。
- 「ひとことでまとめると：」の予告のコロンは実はAIの痕跡だ（人は1,000字あたり0.08か所、AIは0.30か所）が、このときは直さなかった。全体でこの1か所だけだ。

> 訳注: 字数（763字、265字）は中国語の原稿の値。「実は」は中国語の「其实」の訳で、元の原稿の「其实」3つと完成稿の1つに対応させている。

## 二、人名: 同じ人でも、1か所は残し1か所は削る

**元の原稿**

> 歸藏は言う。豆包のメモリー機能がうっとうしいのは、ひとこと話すと毎日のようにその話を蒸し返してきて、こちらがもう済ませたことでもまだ持ち出してくるからだ。彼はここでの問題を、目標と情報が混同されていることだとまとめた……歸藏は言う。彼は以前、Chat で自分の To-Do リストを管理しようとして、滴答清单（TickTick）をやめてしまった。1年たってみると何ひとつ管理できておらず、また滴答清单を使うようになった。

**完成稿**

> 豆包のメモリー機能がうっとうしいのは、ひとこと話すと毎日のようにその話を蒸し返してきて、こちらがもう済ませたことでもまだ持ち出してくるからだ。問題は、目標と情報が混同されていることにある。……歸藏は以前、Chat で自分の To-Do リストを管理しようとして、滴答清单をやめてしまった。1年たってみると何ひとつ管理できておらず、また使うようになった。

同じ話し手でも、前半では名前を削り、後半では名前を残した。違いはこうだ。前半はひとつの判断で、誰にでも言える。名前を付けても記事がくどくなるだけだ。後半は本人の体験で、本人にしか語れない。

同じ理由で残したものは次のとおり。

- `杨攀は今年の上半期、あるスライドで、2027 年のAI製品がまだユーザーに Key、MCP、Skill といった概念を話題にさせているなら、大きくはなれないと話した。`（本人の講演で、出所をたどれる）
- `橘子は元 Google カレンダーのプロダクトマネージャーとこの件を話したことがある。そのプロダクトマネージャーによると……`（一次情報源で、相手の名前を出さないのも妥当だ。これは紹介であって、本人が名乗り出て語ったものではないからだ）
- `歸藏は2〜3日ひんぱんに使ったが、無料のトークンは2〜3％しか使わなかった。`（使ってみた体験）

反対の書き方:「ある業界関係者は、Muse は新しいストアだと指摘する」。人がいるなら人を書く。

## 三、見出し: 名詞句から読者の問いへ

| 元の原稿 | 完成稿 |
|---|---|
| 三、同じことをした前の世代は OpenClaw という | 三、Muse と OpenClaw の違いは何か？ |
| 四、本当に難しいのは人をうんざりさせないこと | 四、Muse の製品は単純に見えて、細部まで作り込まれている |
| 五、目に見える結果 | 五、カレンダーは一般の人に本当に必要か？ |

「目に見える結果」のような見出しでは、読者は読み終えても次の段落が何の話か分からない。問いの形に変えると、読者は問いを持って読み進め、答えも最初に示さなくてよくなる。

## 四、削る: 削ったものはどれも別の問いに答えていた

段落ごと削ったものは次のとおり。

- Manus の小ネタ（「Manus から an を取ると Muse」）。この節は株価と業界の認識の話で、小ネタはそれに答えていない。
- Amazon が Muse をブロックした話、Shopify の株価。ついでに便乗した話題だ。
- 橘子がサイクリング用のアプリを書いた経験、新しい Siri の出来の悪さ、iOS の2つの技術的な進展。第4節の問いは「製品の使い心地がなぜこれほど違うのか」で、これらは別の話だ。
- 橘子が自社製品の「心記」機能を例に挙げた部分。自分の製品の引用だ。

1つも削らなかったものは次のとおり。

- 具体的な数字と仕様: `iPhone 18 Pro Max なら『サイバーパンク2077』を動かしても問題ない`、`2インチの画面、前後のカメラ、音声入力、動画の入出力、5G と eSIM`。
- 情景が浮かぶ元の言葉: `奥さんとはそういうふうに話すんですか？`、`なんでこんなことに人生を無駄にしなきゃいけないんだ。`
- 一次の体験: `無料のトークンは2〜3％しか使わなかった。`

削る基準は「それがこの節の問いに答えているか」で、「この段落はよく書けているか」ではない。節を先に決めてから削るのもそのためだ。構成が決まって初めて、どの段落が脱線しているかが分かる。

## 五、原文を使う: 同じ内容の2つの書き方

別の回（英語の1対1のインタビュー、Invest Like the Best の Noah Shinn）から取った。第1版は全体で直接引用が0か所で、ゲストの言葉はすべて要約に書き直されていた。著者の評価は「書き直しすぎ。原文があるなら原文を使って」だった。

**第1版（要約）**

> 彼は、そんな世界は作りたくないと言う。消費者向けのプラットフォームの多くはユーザーに無料で、広告に頼り、ブランドはお金を払って、本当は必要ないかもしれないものを人に買わせている。彼は技術者として、そんな世界は作りたくない。
>
> 安全を彼は2つに分ける。1つは機密情報の保存、もう1つはまったく新しい問題だ。
>
> 変化は3週目に現れた。4割のユーザーが個人のクレジットカードを1枚それに預けた。

**第2版（引用＋段落の冒頭で前を受ける）**

> 消費者向けのプラットフォームの多くは別の姿をしている。ユーザーには無料で、ユーザーには広告が送られ、ブランドはお金を払って、本当は必要ないかもしれないものを人に買わせている。「よく言われることですが、お金を払っていないなら、あなたが商品なんです。プログラマーとして、技術者として、私はそんな世界を作りたくない」
>
> 彼らの原則は、ユーザーが常に自分のデータを管理することだ。渡したいだけ渡し、取り戻したければいつでも取り戻せる。信頼はこうして育つ。3週間のうちに、4割のユーザーが個人のクレジットカードを1枚それに預けた。

変えた点は次のとおり。

- 判断と感情のこもった言葉は、すべて引用に戻し、前に「彼は言う」を付けた。背景の説明や前後をつなぐ部分は、引き続き地の文にした。直したあと、直接引用が占める漢字の割合は0から35％に上がった。
- 段落の冒頭に毎回自己完結した判断（「安全を彼は2つに分ける」「変化は3週目に現れた」）を置くのをやめ、前の段落の流れを受けるか、場面からすぐ入るようにした。直したあと、段落冒頭の断定文は34％から30％に下がった。
- 「信頼はこうして育つ」のような書き手の判断の文は、段落の途中や終わりに置き、頭には置かない。
- 冒頭で読者のために描いた場面（「彼は向かいに座っている」「番組の冒頭で彼はある問いを投げかけた」）を削り、最初の段落ではこの回が誰と誰の話かをすぐ示した。

**第3版: かぎかっこを半分に減らし、つなぎの言葉を最短にする**

第2版は著者から2回差し戻された。1回目は、かぎかっこが多すぎるという指摘だった。「原文を多く使えと言ったのであって、全部かぎかっこに入れろとは言っていない。これは読んでいて疲れる」。2回目は、自分でこしらえたつなぎの文が重すぎるという指摘だった。「まとめのつなぎは実はすごく単純でいい。たとえば、支払いの話になると、彼は言う。ユーザーの利用場面の話になると、彼は言う。収益化の話になると、彼は言う。あるいは各章で一度人名を出すのでもいい」。

直し方は2つ。

- かぎかっこを33か所から18か所に減らし、本当に情景が浮かぶ言葉、重みのある言葉にだけ残した（電話をかけた部分、task accomplisher のひとこと、「今夜はニューヨークにいる」）。それ以外の元の言葉は言い回しを保ったまま地の文に格下げした（`彼は、シンプルな画面と限られた能力を混同したくないと言う`）。割合は36％から23％に下がった。
- 自分でこしらえたつなぎの文はすべて短い導入に替えた。`支払いの話になると、彼は言う。……`、`利用場面の話になると、彼は車の例を挙げた`、`コストの話になると、彼は言う……`。各節の冒頭で一度人名を出す。
