# 言葉についての必須の制約

このリストのルールは2種類に分かれる。1つは実測の裏付けがあるもの（生成された文章と人が書いた文章、629本・283万字の対照コーパスを集計して出したもの）、もう1つは著者本人が原稿を直す中で1つずつ決めたものだ。どちらも出所を明記しているので、どれだけ重く扱うかは自分で判断してほしい。

> 訳注: 以下の基準値、字数、例文は、すべて中国語の文章についてのものだ。日本語の文章にそのまま当てはまるかは確かめられていない。

## 一、実測の裏付けがあるもの

出所: [lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone)（MIT）。コーパスは5つのモデルが生成した300本と人が書いた329本で、95,551文、45,721段落。人の側のコーパスは公開されておらず、手元で計算し直せないので、以下の基準値はその README の引用に従う。

| 特徴 | 人（1,000漢字あたり） | AI（1,000漢字あたり） | 倍率 |
|---|---|---|---|
| ダッシュ —— | 0.80 | 2.38 | 3.0 |
| 対比構文「XではなくY」 | 0.22 | 0.73 | 3.4 |
| 予告のコロン（「ひとことでまとめると：」） | 0.08 | 0.30 | 3.8 |
| 擬人化した比喩（「指導者のように」） | 0.002 | 0.014 | 7.3 |
| 序数詞を小見出しにする | 0.06 | 0.19 | 3.1 |
| 中身のない文で箇条書きを導く（「……：」のあとに箇条書き） | 0.03 | 0.11 | 3.7 |
| 動詞の名詞化（「最適化を行った」） | 0.005 | — | — |

最も強いのは段落レベルの項目だ。**最初の段落以外で、前を受けない評言から始まる段落の割合は、人が0.14％、AIが0.62％で、相関係数は4.4。** 前を受けない評言とは段落の冒頭にいきなり「注目すべきは」「問題は」「さらに面白いのは」「振り返ってみると」を置き、主語も前の文も受けない書き方のことだ。人が文章を書くとき、新しい段落は前の段落の話題を受けるか、主語を持つ。モデルは段落ごとに新しく論評の文を立てたがる。

材料の密度は別に数える。人は1,000字あたり具体的な材料（数字、固有名詞、時期、数量）が17.92個、AIは6.34個。この項目は言葉づかいのどのルールよりも致命的だ。**なめらかなのに材料がないことが、AIっぽさの主な原因だ。**

### 世間の思い込みと逆の3つ

この3つは、この研究でいちばん価値のある部分だ。SNSで出回っている「AIっぽさを消す」助言とちょうど逆だからだ。

- **人はAIの2.4倍、比喩を使う。** だから「人らしく」見せるために比喩を避けてはいけない。
- **本文での問いかけは、人が1,000字あたり1.83か所、AIが0.10か所で、17倍の差がある。** 問いかけが少ないことがAIっぽさで、多いことが人らしさだ。記事の小見出しを問いの形（「カレンダーは一般の人に本当に必要か？」）にするのは、減点ではなく加点だ。
- **文の長さのばらつきは0.87で、差がない。** 文の長さを無理にばらつかせても意味がない。

## 二、著者が決めた必須の制約

最初の6つは1つずつ指摘されたもので、そのときの言葉をあとに書いている。

1. **ダッシュ（——）を使わない。** 中国語と英語が混ざる原稿で、このルールがいちばん破られやすい。
2. **「XではなくYだ」を使わない。「……ではなく……である」「……にあるのではなく……にある」も使わない。**
3. **まとめ口調を使わない**: 本質的には、核心は、つまるところ、言い換えれば、注目すべきは、特筆すべきは、以上をまとめると、結局のところ。
4. **対句を使わない。** 例:「速さは周回数に、方向は採点する人に」。このときの言葉は「まったく人間の表現じゃない」。中国語で、2つに割って左右対称にし、述語を省くこの言い方は、モデルが自分で発明した文体だ。
5. **比喩を用語として使わない。** 比喩は書いていいが、名前として立てたうえで何度も引いてはいけない（「周回数」「ハンドル」「天井」）。このときの言葉:「わざわざ話を複雑にしてる、すごく単純な言葉なのに」。
6. **目的語を省かない。** 例:「それがずっと押さえているのは、1回間違えたときの代償だ」。「押し下げる」が「押さえる」の1字に削られ、主語も目的語もなくなっている。このときの言葉:「あなたはいつも目的語を省く」。
7. **一度決めた言葉はそのあともそのまま使い、類義語に替えない。** このときの言葉:「前で言ったものは後ろでもそのまま使う、それが進化でしょう。毎回新しいのを作り出して、全然賢くない」。
8. **1段落に1つの意味、2〜4文。** 長い段落は分け、短い段落を無理に寄せ集めない。
9. **文頭に接続詞を置かない**: しかし、したがって、このほか、それと同時に、言い換えれば。
10. **本文に太字と箇条書きを使わない。** 並べたい内容は文にする。

## 三、数字の書き方

実測の基準: ある5,730漢字の完成稿には、アラビア数字の文字が16個しかなかった。同じシリーズの別の記事はその6倍だった。

習慣としては、話し言葉の数は漢数字で書き（百分之十、两万亿、五十万、一百克）、型番、年、英語の単位が付く技術仕様はアラビア数字で書く（iPhone 18 Pro Max、5G、eSIM、2027 年）。1本の記事の中では前後でそろえ、半分は漢数字、半分はアラビア数字にはしない。

## 四、自己チェック

```bash
python3 scripts/check_style.py 完成稿.md
```

スクリプトは上の1種類目のルールに沿って動き、項目ごとの該当数と実例を出して、人の基準値と比べる。字面しか見ないので、本当に痕跡かどうかは自分で読んで判断する。よくある誤検出は、かぎかっこの中の元の言葉、対話形式で同じ構造の文が続く箇所、読点（、）の多い列挙だ。

実測の参考: このルールで直した5,000字の完成稿は、ダッシュ、対比構文、まとめ口調、序数詞の小見出し、動詞の名詞化、中身のない文がすべてゼロだった。予告のコロンが「ひとことでまとめると：」の1か所でだけつまずき、ほかに材料の密度が低めだった。
