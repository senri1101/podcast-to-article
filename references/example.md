# 対照例

以下はすべて、同じ回のポッドキャスト（Next Token 第4回、Muse の部分）を実際に直したときのものだ。元の原稿は録音どおりに話し手ごとに並べた版で、完成稿は公開した版だ。

> 訳注: 原文は中国語の原稿を例にしている。ここでは日本語に訳して示すので、字数は中国語の原稿での値で、言い回しの細部も訳したものだ。

## 〇、まず事実メモの形を見る

記事を書く前に作る事実メモは、話題ごとにまとめ、1行に1項目を書き、括弧に章番号を入れる。

```
## A. 大ヒットした

1. どのソフトウェアも、そのコネクタストアに入ると株価が1日で最低でも10％上がり、13％上がったものもある。Meta は2兆ドルまで上がった。（06）
2. かつて Alexandr Wang の会社を買収したとき、多くの人が、ザッカーバーグは頭がおかしい、数百億ドルでこんなものを買うなんて、と罵った。今ではその人物が、1日で Meta の時価総額を2兆ドル押し上げた。（06）
3. 楊攀: Muse は新しいストアだ。前はアップルのストアに載せていたが、今載せる先はエージェントだ。（06）
4. 1日のアクティブユーザーは50万人しかいない。（06）
5. 中国語のネットの世界では、Meta の本当の価値が知られていない。Meta の主な製品を、私たちがふだん使わないからだ。Threads の1日のアクティブユーザーは実はとっくに Twitter を超えていて、Facebook の広告収入はすさまじい。楊攀はこれを「アメリカのテンセント」と呼んだ。（06）
6. 楊攀は大手IT企業の社内で講演を重ね、こう話した。Doubao はもともと数億人向けの製品だったが、Codex と WorkBuddy が流行ったので1億人向けに方向を変えた。結局はまた数億人向けに戻らなければならないのに、その判断を Muse に1か月でひっくり返された。（09）
7. 橘子: Muse はAIバブルを新しい頂点に押し上げた。1日のアクティブユーザーが1億人いれば、仮想コンピュータが1億台いる。（09）
```

3、5、6、7の項目にも名前を書いていることに注意してほしい。事実メモの段階では、名前を全部残す。それが誰の情報で、どこまで信用できるかを分かるようにしておくためだ。どの名前を記事に残すかは、記事を書く段階で決める。

>

変えた点は次のとおり。

- 「Xは言う」「Xのまとめでは」の6か所のうち、5か所を削った。残したのは楊攀の1か所だけだ。その段落は楊攀しか持っていない情報なので、本人の名前で示す必要がある。
- 長い文を分けた。「楊攀は先週、いくつかの大手IT企業の社内で講演をしたばかりで、彼によると Doubao は……」を2文にし、講演の話を独立した短い文にした。
- 「多くの人が、ザッカーバーグは頭がおかしい、数百億ドルでこんなものを買うなんて、と罵った」を、「世間からはさんざん罵られ、いったい何を買ったんだと言われた」に変えた。元の文は、話し手がほかの人を評した言葉だ。そのまま写すと、記事の書き手が人を罵っていることになる。世間の反応として書けば、勢いは残り、書き手が責任を負うこともない。あわせて主語の「Meta」を補った。元の「かつて Alexandr Wang の会社を買収したとき」には、誰が買収したかが書かれていなかった。
- 3つの「実は」のうち2つを削った。話し言葉で繰り返される接続語は、文字にするととても目障りだ。
- 「ひとことでまとめると：」という予告のコロンも、実はAIらしい書き方だ（人は1,000字あたり0.08か所、AIは0.30か所）。このときは直さなかった。記事全体でこの1か所だけだった。

> 訳注: 字数（763字、265字）は中国語の原稿の値。「実は」は中国語の原稿にある同じ副詞の訳で、元の原稿の3つと完成稿の1つに対応させている。

## 二、名前: 同じ人でも、残す所と削る所がある

**元の原稿**

> 歸藏は言う。Doubao のメモリー機能がうっとうしいのは、ひとこと話すと毎日その話を蒸し返してきて、もう済ませたことでもまだ持ち出してくるからだ。彼はここでの問題を、目標と情報が混同されていることだとまとめた……歸藏は言う。彼は以前、Chat で自分の To-Do リストを管理しようとして、TickTick をやめてしまった。1年たってみると何ひとつ管理できておらず、また TickTick を使うようになった。

**完成稿**

> Doubao のメモリー機能がうっとうしいのは、ひとこと話すと毎日その話を蒸し返してきて、もう済ませたことでもまだ持ち出してくるからだ。問題は、目標と情報が混同されていることにある。……歸藏は以前、Chat で自分の To-Do リストを管理しようとして、TickTick をやめてしまった。1年たってみると何ひとつ管理できておらず、また使うようになった。

同じ話し手でも、前半では名前を削り、後半では残した。前半はただの判断で、誰が言ってもおかしくない。名前を付けても記事がくどくなるだけだ。後半は本人の体験で、本人にしか語れない。

同じ理由で名前を残したものは次のとおり。

- `楊攀は今年の上半期、あるスライドで、2027 年のAI製品がまだユーザーに Key、MCP、Skill といった概念を意識させているなら、大きくはなれないと話した。`（本人の講演なので、出どころをたどれる）
- `橘子は、Google カレンダーの元プロダクトマネージャーとこの件を話したことがある。そのプロダクトマネージャーによると……`（直接聞いた話だ。相手の名前を出さないのも妥当で、相手が自分の発言として語ったのではなく、橘子が紹介しているからだ）
- `歸藏は2〜3日、何度も使ってみたが、無料のトークンは2〜3％しか使わなかった。`（使ってみた体験）

反対の書き方は「ある業界関係者は、Muse は新しいストアだと指摘する」だ。言った人がいるなら、その人の名前を書く。

## 三、見出し: 名詞句から、読者が持つ問いへ

| 元の原稿 | 完成稿 |
|---|---|
| 三、同じことをした前の世代は OpenClaw という | 三、Muse と OpenClaw の違いは何か？ |
| 四、本当に難しいのは人をうんざりさせないこと | 四、Muse の製品は単純に見えて、細部まで作り込まれている |
| 五、目に見える結果 | 五、カレンダーは一般の人に本当に必要か？ |

「目に見える結果」のような見出しでは、読者は見出しを読んでも、その節が何の話か分からない。問いの形にすれば、読者は問いを持って読み進めるので、答えを最初に示さなくてもいい。

## 四、削る: 削った部分は、どれも別の問いに答えていた

段落ごと削ったものは次のとおり。

- Manus の小ネタ（「Manus から an を取ると Muse」）。この節は株価と業界の受け止め方の話で、小ネタはそれに答えていない。
- Amazon が Muse を締め出した話と、Shopify の株価。ついでに話題に便乗しただけだ。
- 橘子がサイクリング用のアプリを作った経験、新しい Siri の出来の悪さ、iOS の2つの技術的な進歩。第4節の問いは「製品の使い心地がなぜこれほど違うのか」で、これらは別の話だ。
- 橘子が自社製品の「心記」機能を例に挙げた部分。自分の製品の宣伝になる。

1つも削らなかったものは次のとおり。

- 具体的な数字と仕様: `iPhone 18 Pro Max なら『サイバーパンク2077』を動かしても問題ない`、`2インチの画面、前後のカメラ、音声入力、動画の入出力、5G と eSIM`。
- 情景が浮かぶ本人の言葉: `奥さんとはそういうふうに話すんですか？`、`なんでこんなことに人生を無駄にしなきゃいけないんだ。`
- 本人が使ってみた体験: `無料のトークンは2〜3％しか使わなかった。`

削るかどうかは「この節の問いに答えているか」で決め、「この段落はよく書けているか」では決めない。節を先に決めてから削るのも、そのためだ。構成が決まって初めて、どの段落が脱線しているかが分かる。

## 五、本人の言葉を使う: 同じ内容の2つの書き方

別の回（英語の1対1のインタビュー、Invest Like the Best の Noah Shinn）の例だ。第1版には直接の引用が1つもなく、ゲストの言葉はすべて要約に書き直されていた。著者の評価は「書き直しすぎ。原文があるなら原文を使って」だった。

**第1版（要約）**

> 彼は、そんな世界は作りたくないと言う。消費者向けのプラットフォームの多くはユーザーには無料で、広告で稼ぎ、ブランドはお金を払って、本当は必要ないかもしれないものを人に買わせている。彼は技術者として、そんな世界は作りたくない。
>
> 安全の問題を、彼は2つに分ける。1つは機密情報の保管で、もう1つはまったく新しい問題だ。
>
> 変化は3週目に現れた。4割のユーザーが、個人のクレジットカードを1枚、このアシスタントに預けた。

**第2版（引用を使い、段落の最初で前の段落を受ける）**

> 消費者向けのプラットフォームの多くは、別のやり方をしている。ユーザーには無料で、ユーザーに広告を見せ、ブランドはお金を払って、本当は必要ないかもしれないものを人に買わせる。「よく言われることですが、お金を払っていないなら、あなたが商品なんです。プログラマーとして、技術者として、私はそんな世界を作りたくない」
>
> 彼らの原則は、ユーザーがいつでも自分のデータを管理できることだ。渡したいだけ渡し、取り戻したければいつでも取り戻せる。信頼はこうして育つ。3週間のうちに、4割のユーザーが、個人のクレジットカードを1枚、このアシスタントに預けた。

変えた点は次のとおり。

- 判断と感情がこもった言葉は、すべて引用に戻し、前に「彼は言う」を付けた。背景の説明や、話と話をつなぐ部分は、これまでどおり地の文にした。その結果、直接の引用が占める字数の割合は0から35％に上がった。
- 段落の最初に毎回言い切りの判断（「安全の問題を、彼は2つに分ける」「変化は3週目に現れた」）を置くのをやめ、前の段落を受けるか、場面からすぐ入るようにした。言い切りの文から始まる段落は、34％から30％に下がった。
- 「信頼はこうして育つ」のような書き手の判断の文は、段落の途中か終わりに置き、最初には置かない。
- 冒頭で読者のために描いた場面（「彼は向かいに座っている」「番組の冒頭で、彼はある問いを投げかけた」）を削り、最初の段落で、この回が誰と誰の対談かをすぐ示した。

**第3版: かぎかっこを半分に減らし、つなぎの言葉を最短にする**

第2版は著者から2回差し戻された。1回目は、かぎかっこが多すぎるという指摘だった。「原文を多く使えと言ったのであって、全部かぎかっこに入れろとは言っていない。これは読んでいて疲れる」。2回目は、自分で作ったつなぎの文が重すぎるという指摘だった。「まとめのつなぎは実はすごく単純でいい。たとえば、支払いの話になると、彼は言う。ユーザーが使う場面の話になると、彼は言う。収益化の話になると、彼は言う。あるいは各章で一度人名を出すのでもいい」。

直し方は2つ。

- かぎかっこを33か所から18か所に減らし、本当に情景が浮かぶ言葉と、重みのある言葉にだけ残した（電話をかけた場面、task accomplisher のひとこと、「今夜はニューヨークにいる」）。それ以外の本人の言葉は言い回しを変えずに地の文に移した（`シンプルな画面と、できることが少ないことを混同したくない、と彼は言う`）。割合は36％から23％に下がった。
- 自分で作ったつなぎの文はすべて短い前置きに替えた。`支払いについては、こう話す。……`、`使う場面については、車の例を挙げた`、`コストについては、こう話す。……`。各節の冒頭で一度だけ人名を出す。
