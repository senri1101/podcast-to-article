# 言葉づかいの決まり

ここに並べたルールは2種類ある。1つは実測の裏付けがあるルールで、生成された文章と人が書いた文章を比べたコーパス（629本、283万字）の集計から出したものだ。もう1つは、著者が原稿を直しながら1つずつ決めたルールだ。どちらにも出どころを書いたので、どれだけ重く扱うかは読む人が判断してほしい。

> 訳注: 以下の基準値、字数、例文は、すべて中国語の文章についてのものだ。日本語の文章にそのまま当てはまるかは確かめられていない。

## 一、実測の裏付けがあるルール

出どころ: [lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone)（MIT）。コーパスは、5つのモデルが生成した文章300本と人が書いた文章329本で、95,551文、45,721段落。人の側のコーパスは公開されておらず、手元で計算し直せないので、基準値はその README に書かれた値を使っている。

| 特徴 | 人（1,000字あたり） | AI（1,000字あたり） | 倍率 |
|---|---|---|---|
| ダッシュ —— | 0.80 | 2.38 | 3.0 |
| 対比構文「XではなくY」 | 0.22 | 0.73 | 3.4 |
| 予告のコロン（「ひとことでまとめると：」） | 0.08 | 0.30 | 3.8 |
| 人にたとえる比喩（「指導者のように」） | 0.002 | 0.014 | 7.3 |
| 序数詞を小見出しにする | 0.06 | 0.19 | 3.1 |
| 中身のない文で箇条書きを始める（「……：」のあとに箇条書き） | 0.03 | 0.11 | 3.7 |
| 動詞の名詞化（「最適化を行った」） | 0.005 | — | — |

いちばん差がはっきり出たのは、段落の始め方だ。**最初の段落を除き、前の段落を受けずに論評から始まる段落の割合は、人が0.14％、AIが0.62％で、相関係数は4.4だった。** 前の段落を受けない論評とは、段落の最初にいきなり「注目すべきは」「問題は」「さらに面白いのは」「振り返ってみると」と書き、主語も前の話も受けない書き方のことだ。人が書く文章では、新しい段落は前の段落の話を受けて始まるか、主語を立てて始まる。モデルは段落ごとに論評の文を新しく立てたがる。

具体的な材料の多さは別に数えている。数字、固有名詞、時期、数量といった材料は、人の文章では1,000字あたり17.92個、AIの文章では6.34個だった。これは言葉づかいのどのルールよりも重い。**文章がなめらかなのに材料が少ないことが、AIらしさのいちばんの原因だ。**

### 世間の思い込みと逆の3つ

この研究でいちばん価値があるのは、次の3つだ。SNSで広まっている「AIっぽさを消す」助言と、ちょうど逆の結果が出ている。

- **人はAIの2.4倍、比喩を使う。** 人らしく見せようとして比喩を避けてはいけない。
- **本文の中の問いかけは、人が1,000字あたり1.83か所、AIが0.10か所で、17倍の差がある。** 問いかけが少ないほうがAIらしく、多いほうが人らしい。記事の小見出しを問いの形（「カレンダーは一般の人に本当に必要か？」）にするのは、減点ではなく加点だ。
- **文の長さのばらつきは0.87で、人とAIに差はない。** 文の長さをわざとばらつかせても意味がない。

## 二、著者が決めたルール

最初の6つは、著者が1つずつ指摘したもので、そのときの言葉も書き添えた。

1. **ダッシュ（——）を使わない。** 中国語と英語が混ざる原稿では、このルールがいちばん破られやすい。
2. **「XではなくYだ」を使わない。「……ではなく……である」「……にあるのではなく……にある」も使わない。**
3. **まとめ口調を使わない**: 本質的には、核心は、つまるところ、言い換えれば、注目すべきは、特筆すべきは、以上をまとめると、結局のところ。
4. **対句を使わない。** 例:「速さは周回数に、方向は採点する人に」。このとき著者は「まったく人間の表現じゃない」と言った。2つに割って左右をそろえ、述語を省くこの言い方は、モデルが中国語で勝手に作り出した文体だ。
5. **比喩を用語のように使わない。** 比喩を書くのはいいが、比喩に名前を付けて何度も持ち出してはいけない（「周回数」「ハンドル」「天井」）。このとき著者は「わざわざ話を複雑にしてる、すごく単純な言葉なのに」と言った。
6. **目的語を省かない。** 例:「それがずっと押さえているのは、1回間違えたときの代償だ」。「押し下げる」が「押さえる」の1字に削られ、主語も目的語もなくなっている。このとき著者は「あなたはいつも目的語を省く」と言った。
7. **一度決めた言葉はそのあともそのまま使い、類義語に替えない。** このとき著者は「前で言ったものは後ろでもそのまま使う、それが進化でしょう。毎回新しいのを作り出して、全然賢くない」と言った。
8. **1段落で言うことは1つにし、2〜4文で書く。** 長い段落は分け、短い段落を無理にまとめない。
9. **文の最初に接続詞を置かない**: しかし、したがって、このほか、それと同時に、言い換えれば。
10. **本文に太字と箇条書きを使わない。** 並べたい内容は文で書く。

## 三、数字の書き方

実測では、5,730字のある完成稿に、アラビア数字の文字は16個しかなかった。同じシリーズの別の記事にはその6倍あった。

著者の書き方では、話し言葉の中の数は漢数字で書き（百分之十、两万亿、五十万、一百克）、型番、年、英語の単位が付く技術仕様はアラビア数字で書く（iPhone 18 Pro Max、5G、eSIM、2027 年）。1本の記事の中では書き方をそろえ、漢数字とアラビア数字を半々に混ぜない。

## 四、自己チェック

```bash
python3 scripts/check_style.py 完成稿.md
```

スクリプトは一の実測のルールに沿って項目ごとの件数と実例を出し、人の基準値と並べる。字面しか見ないので、本当にAIらしい書き方かどうかは自分で読んで判断する。よくある誤検出は、かぎかっこの中の本人の言葉、対話の形で同じ構造の文が続く箇所、読点（、）で区切った長い列挙だ。

実測の例: このルールで直した5,000字の完成稿では、ダッシュ、対比構文、まとめ口調、序数詞の小見出し、動詞の名詞化、中身のない文がすべて0件だった。引っかかったのは「ひとことでまとめると：」という予告のコロン1か所と、具体的な材料がやや少ないことだけだった。
